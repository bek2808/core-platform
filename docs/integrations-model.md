# Подключение к ЕРСП: модель данных

Согласовано с Бекзодом 20.10.2026. Раздел «Интеграции → Подключение к ЕРСП»:
данные для входа в ЕРСП вводит администратор своей страховой через экран,
а не командой на сервере — это нужно мультиарендному продукту
(у каждой страховой свои данные от НАПП).

Код: `app/integrations/models.py` (таблицы), `app/config/crypto.py` (шифрование),
`app/integrations/ersp.py` (клиент ЕРСП).

## Главные принципы

- **У каждой страховой своя карточка подключения.** Внутри — два блока:
  боевая среда и песочница. Блоки создаются вместе с карточкой и не удаляются.
- **client_id и логин видны, client_secret и пароль — только вводятся.**
  На экране — «задан ••••» и «Изменить»; обратно значение не показывается
  никому, даже суперпользователю.
- **В базе — только шифр.** Ключ шифрования — в секрете Podman
  `core_encryption_key`, в резервных копиях базы лежит только шифр.
  Открытый пароль база не примет даже в обход приложения (проверка в базе).
- **Копии ключа нет** (решение 20.10). Потерян ключ — данные для входа
  вводятся заново через экран (их можно получить у НАПП).
- **Токен — не в базе.** Он остаётся в tmpfs контейнера (оперативная память),
  отдельно для каждой страховой и среды: ЕРСП не отзывает старые токены,
  токен фактически бессрочный пароль.
- **Журнал.** Изменения пишутся в журнал изменений, как у всех таблиц,
  которые правят люди. Для client_secret и пароля — только факт смены
  («*** → ***»), не значение и не шифр.
- **Ничего не удаляем.** Страховая перестала работать с ЕРСП — данные для входа
  стираются (пустое значение), записи остаются.

## Среда по группам операций

| Группа | Среда | Меняется |
|---|---|---|
| Справочники ЕРСП | боевая | только коммитом (в песочнице справочники неполные) |
| Провайдер (организация по ИНН и др.) | боевая | только коммитом |
| Отправка полисов | из карточки страховой; по умолчанию песочница | на экране; переход на боевую — с подтверждением и записью в журнал |

## Таблицы

### Подключение к ЕРСП (`integrations_erspconnection`)

Одна строка на страховую.

| Поле | Правило |
|---|---|
| страховая компания | обязательна, одна карточка на страховую (уникальность в базе) |
| отправка полисов | `prod` или `sandbox` (проверка в базе), по умолчанию `sandbox` |
| создал / изменил, время | как у всех таблиц с журналом (`TrackedModel`) |

### Данные для входа в ЕРСП (`integrations_erspcredentials`)

Одна строка на среду в карточке (уникальность «карточка + среда» в базе).

| Поле | Хранится | Показывается | В журнале |
|---|---|---|---|
| среда | `prod` / `sandbox` (проверка в базе) | да | — (не меняется) |
| client_id | как есть, без пробелов по краям | да | было → стало |
| логин | как есть, без пробелов по краям | да | было → стало |
| client_secret | шифр `v1:…` или пусто (проверка в базе) | «задан ••••» / «не задан» | `***` |
| пароль | шифр `v1:…` или пусто (проверка в базе) | «задан ••••» / «не задан» | `***` |

Изменения блока видны в «Истории» карточки подключения.

## Шифрование

- AES-GCM, ключ 32 байта (библиотека `cryptography`).
- Шифр привязан к своему месту: страховая, среда, поле. Шифр, скопированный
  в чужую строку (другая страховая или среда), не расшифровывается.
- Одно и то же значение каждый раз шифруется по-разному: по шифрам нельзя
  понять, что у двух страховых одинаковый пароль.
- Шифр начинается с версии ключа (`v1:`) — задел на будущую смену ключа.
- Ключ заводится скриптом `bin/encryption-key`: создаётся сразу внутри
  секрета и на экран не выводится. Замена ключа (`--replace`) делает все
  шифры нечитаемыми — только если ключ потерян или раскрыт.

## Права

Группа «Администратор интеграций»: карточка подключения своей страховой
и журнал обмена своей страховой. Контрагенты и справочники — в других
группах; человеку можно дать несколько групп.

Мультиарендность: сотрудник со страховой видит только её карточку;
администратор системы без страховой видит все.

## Экран

«Интеграции -> Подключение к ЕРСП». Сотрудник страховой сразу попадает
в карточку своей страховой (она создаётся при первом открытии);
администратор системы без страховой видит список всех.

- Блок среды: client_id, client_secret, логин, пароль. Поле client_secret
  и пароля всегда пустое; пусто при сохранении - не менять; «стереть» -
  удалить значение. Пароль сохраняется как введён, с пробелами.
- «Проверить подключение» - новый вход в ЕРСП с сохранёнными данными;
  итог - сообщением на карточке, запрос - в журнале обмена.
- «Токен» - когда получен, до какого времени действует по словам ЕРСП,
  счётчик «осталось». После перезапуска контейнера токена нет до первого
  запроса. После смены данных для входа токен забывается.
- «Среда отправки полисов» - отдельная страница; на боевую - только
  с отметкой подтверждения.
