# Справочник контрагентов: модель данных

Согласовано с Бекзодом 19.10.2026. Первый шаг — юридические лица;
физические лица (и ИП как физлицо с признаком «ИП») добавляются позже
отдельной таблицей, общая часть при этом не меняется.

Исходные требования: [requirements/counterparties-legal-entities.md](requirements/counterparties-legal-entities.md).

Обозначения источника: **П** — провайдер ЕРСП (`/api/provider/inn`),
**Р** — ручной ввод, **С** — справочник ЕРСП. Звёздочка в колонке «ЕРСП» —
поле обязательно в ЕРСП.

## Главные принципы

- **Один клиент — одна запись.** Перед созданием ищем по ИНН (у физлиц — по ПИНФЛ);
  в базе стоит ограничение уникальности, поэтому дубль не появится даже при ошибке в коде.
- **Каждый контрагент принадлежит одной страховой компании** (мультиарендность).
  Список клиентов одной страховой другая не видит. ИНН уникален внутри страховой.
- **Карточку можно сохранить неполной.** Проверок две:
  1. при сохранении — только формат (9 цифр, 14 цифр и т. п.);
  2. перед отправкой в ЕРСП — полнота для конкретной роли в полисе
     и признака «иностранная»; система показывает, чего не хватает.
- **Ничего не удаляем.** Контрагент, банк, страховщик уходят в архив
  (на них ссылаются полисы).
- **История.** Любое изменение пишется в журнал: было → стало, кто, когда, источник.
  Полис хранит снимок реквизитов клиента на день выдачи (появится вместе с полисами).
- **Время** — UTC в базе, показ по Ташкенту. **Деньги** — `Decimal` с валютой.

## Таблицы

### Страховщики ЕРСП (справочник С)

Загружается из ответа ЕРСП (сейчас из файла, позже автоматически).

| Поле | Правило |
|---|---|
| id ЕРСП | главный ключ |
| название | как пришло (нормализованная копия для поиска появится вместе с контрагентами) |
| ИНН (`tin`) | может быть пустым (12 из 49); если заполнен — уникален |

Флаги разрешений (ОСГОП, ОСАГО и т. д.) пока не колонки: станут колонками,
когда по ним появится правило.

### Регионы ЕРСП и формы собственности ЕРСП (справочники С)

- Регионы: id ЕРСП, название на русском, узбекском (латиница и кириллица)
  + наша колонка «код области по СОАТО» — по ней система подсказывает регион
  по коду СОАТО района от провайдера.
- Формы собственности: id ЕРСП, название.

### Районы, валюты, ОКЭД ЕРСП (справочники С, добавлены 20.10)

Файлы прислал Бекзод из ЕРСП; хранятся как пришли (ответ целиком — в `raw`),
убраны только пробелы и переводы строк по краям названий.

- **Районы** (249): id ЕРСП, название, регион. Номер района в ЕРСП — **не код
  СОАТО**: Шайхантахурский — СОАТО 1726277, в ЕРСП 1006; у 9 новых районов
  номера вида 739001080. В данных организации для ЕРСП района нет, поэтому
  в карточке юрлица остаётся СОАТО от провайдера. Связь «СОАТО → район ЕРСП»
  (таблица соответствия по nrm.uz) — когда район понадобится по правилам ЕРСП
  (физлица, объекты страхования).
- **Валюты** (164): id — цифровой код ISO 4217 (860 сум, 840 доллар, 978 евро);
  система опирается на него. Буквенные коды в ЕРСП местами с ошибками
  (евро — `EVR`, гривна — `UAН` с кириллической Н, `TJS` с пробелом) —
  не исправляем, для логики не используем.
- **ОКЭД** (696): id — код строкой (ведущий ноль: 01452). 690 кодов из 5 цифр
  и 6 кодов верхних уровней классификатора из 2–4 цифр (73, 682, 9411) —
  храним как есть. Русские названия местами обрезаны — показывается узбекское.

### Основания полномочий и должности (наши справочники)

Для удобства ввода; в ЕРСП это строковые поля. В каждом есть пункт «Иное»
со свободным текстом. Списки собираются по нормативным источникам Узбекистана
отдельным шагом.

Решение 20.10: стартовые списки заводятся сразу миграцией, сверка
с нормативкой и юристом — позже.
- Основания: Устав, Положение, Доверенность, Приказ, Решение,
  Свидетельство о государственной регистрации, Закон или указ, Договор, Иное.
- Должности: Директор, Генеральный директор, Председатель правления,
  Исполнительный директор, Заместитель директора, Заместитель председателя
  правления, Председатель, Начальник, Управляющий, Руководитель филиала,
  Главный бухгалтер, Иное.

| Поле | Правило |
|---|---|
| название | уникально без учёта регистра |
| пункт «Иное» | ровно один на справочник, заводится только миграцией, выключить нельзя |
| порядок в списке | меньше — выше; «Иное» последний (999) |
| действует | лишний пункт не удаляют, а выключают |

### Контрагент (общая карточка)

| Поле | Откуда | ЕРСП | Правило |
|---|---|---|---|
| страховая компания | система | — | |
| тип | система | person / organization | `legal_entity` или `individual` (словом, не числом) |
| отображаемое имя | система | — | для списков и поиска |
| телефон | П `phone` / Р | `phone` (местным обязателен) | местный: `998` + 9 цифр |
| эл. почта | П `email` / Р | `email` (иностранным обязательна) | формат адреса почты |
| регион | С, подсказка по СОАТО | `regionId`* | |
| адрес | П `address` / Р | `address`* | лишние пробелы обрезаются |
| статус | Р | — | действует / архив |
| кто и когда создал, изменил | система | — | UTC |

Сделано 20.10 (решения Бекзода в тот же день):
- Страховая компания подставляется из учётной записи сотрудника и больше
  не меняется; сотрудник видит только контрагентов своей страховой.
  Пользователь без страховой (администратор системы) видит всех и выбирает
  страховую при создании.
- Отображаемое имя — краткое наименование, если его нет — полное. Собирает
  система; в журнал не пишется (пишутся сами наименования).
- Ключ для поиска (`search_text`) — наименования и ИНН в нижнем регистре,
  кириллические буквы-двойники сведены к латинским, апострофы и кавычки
  унифицированы. Поиск в админ-панели — по ключу и точно по ИНН.
  Транслитерации нет: «ИНСОН» не найдёт «INSON».
- Телефон хранится цифрами (`+`, пробелы, скобки, дефисы убираются),
  от 7 до 15 цифр. Необязателен; у местной организации, если заполнен, —
  `998` и 9 цифр. У иностранной обязательна почта (проверка — перед ЕРСП).
- Регион, если пуст, система ставит по первым 4 цифрам кода СОАТО района;
  в журнале — источник «система». Выбранный сотрудником регион не меняется.

| ОКЭД | П `oked` | `oked`* | ссылка на справочник ОКЭД ЕРСП; название — из справочника (поле «вид деятельности» убрано 20.10) |
| ОКПО | П `okpo` | — | 8 цифр |

| номер и дата свидетельства о регистрации | П `regCertificate`, `regCertificateIssueDate` | — | это не страховая лицензия |
| уставный капитал, валюта | П `fund` | — | `Decimal`; валюта — ссылка на справочник валют ЕРСП; от провайдера приходит в сумах |
| форма собственности | С, Р | `ownershipFormId` (страхователю) | провайдер не отдаёт |

Сделано 20.10 (решения Бекзода в тот же день):
- Обязательны при сохранении только **ИНН и полное наименование** — и у местных,
  и у иностранных: без ИНН нельзя проверить дубль. Остальное можно дописать позже.
- ИНН иностранной — от 9 до 20 латинских букв и цифр.
- Страна у местной — всегда UZ (ставится сама), у иностранной — код другой
  страны по ISO 3166-1.
- Уставный капитал — `Decimal` с двумя знаками, не отрицательный;
  валюта — из справочника валют ЕРСП; если капитал указан, а валюта нет —
  сум (860). Капитал без валюты база не примет.
- ОКЭД — только из справочника ЕРСП: код, которого там нет, не сохранится
  (ЕРСП его всё равно не примет при отправке).
- Регион по СОАТО проверяется после каждого сохранения карточки: и когда
  изменили СОАТО, и когда сотрудник очистил регион (ошибка найдена 20.10).
- Переход ОКЭД и валюты с текста на справочники — миграция
  `counterparties/0004`; перед ней на сервере загружаются справочники.
  Прежний «вид деятельности» при откате не восстанавливается (есть в копии).
- Страховая компания хранится и здесь (копия из карточки), чтобы уникальность
  «страховая + ИНН + иностранная» проверяла база. Составная ссылка в базе
  не даёт копии разойтись с карточкой и не даёт сменить страховую у карточки.
- Архив не освобождает ИНН: клиента возвращают из архива, а не заводят заново.
- Повтор ИНН показывается сообщением с наименованием уже заведённого клиента.

| ПИНФЛ | Р | `representativePinfl` |

Сменился руководитель — старая запись закрывается датой, создаётся новая.

Сделано 20.10 (решения Бекзода в тот же день):
- Одновременно может действовать **несколько** представителей (директор
  и заместитель по доверенности); отметка «основной» — у одного, его данные
  уходят в ЕРСП. Основной не может быть с истёкшим сроком («действует по»
  в прошлом). Записи не удаляются.
- Представитель привязан к карточке контрагента; заводится только у организаций.
- Должность и основание — из наших справочников; при «Иное» текст обязателен,
  при обычном пункте текст «Иное» не хранится. Для ЕРСП берётся текст
  (`position_text`, `power_basis_text`).
- ПИНФЛ — ровно 14 цифр (контрольная цифра — после официального источника).
- Серия и номер паспорта хранятся без пробелов, заглавными; **формат пока
  не проверяется** — решим после разбора физлиц (представитель может быть
  иностранцем).
- «Действует по» не раньше «действует с» (проверяет и база).

### Банк (справочник)

МФО (уникален), название (П `bankName`), ИНН банка (Р, один раз на банк —
провайдер его не отдаёт), действует или нет. Новый МФО от провайдера
заводит банк автоматически.

| Поле | Правило |
|---|---|
| МФО | ровно 5 цифр, уникален; пробелы убираются |
| название | лишние пробелы обрезаются |
| ИНН банка | 9 цифр или пусто; **не уникален**: у филиалов одного банка (разные МФО) ИНН может совпадать |
| действует | банк не удаляют, а выключают |

Справочник общий для всех страховых компаний (это банки страны, а не клиенты).
Иностранные банки сюда не заносятся: у счёта пишется название банка текстом.
При ручном вводе счёта неизвестный МФО банк сам не заводит — сначала банк
добавляется в справочник; автоматически это делает только загрузка от провайдера.

### Кто и когда (во всех таблицах, которые правят люди)

Создана, кем; изменена, кем — время в UTC. Пустое «кем» означает «система»
(загрузка, миграция). Общая основа — приложение `audit`, в нём же будет
журнал изменений.

### Счёт

Контрагент, банк (по МФО) или название иностранного банка текстом,
номер счёта, валюта, «основной». В ЕРСП уходит основной счёт
(`checkingAccount`*, `bankName`*, `bankMfo`, `bankInn`).
Местный счёт — 20 цифр. Не больше одного основного счёта у контрагента.

Сделано 20.10:
- Банк — либо из справочника (банк Узбекистана), либо название иностранного
  банка текстом; ровно одно из двух (выбран банк из справочника — текст
  иностранного банка не хранится).
- Номер: в банке Узбекистана — ровно 20 цифр; в иностранном — 5–34 латинских
  буквы и цифры (IBAN и другие). Пробелы убираются, буквы заглавные.
- Валюта — из справочника валют ЕРСП; пусто — сум.
- Основной — один и не закрытый; закрытый счёт не удаляется, а получает
  отметку «закрыт». Номер не повторяется у одного контрагента.
- Проверка кода валюты внутри номера (6–8 знаки) и контрольного ключа с МФО —
  после сверки с официальным источником.

### Журнал изменений

Таблица, запись, поле, было → стало, кто, когда, источник (вручную / провайдер).
Только добавление: правка и удаление запрещены на уровне базы.

Сделано 20.10 (приложение `audit`, таблица `audit_changelog`):

| Поле | Правило |
|---|---|
| когда | UTC, показ по Ташкенту |
| номер изменения | общий у всех полей одного сохранения |
| кто | сотрудник; пусто — система (загрузка, миграция) |
| источник | вручную / провайдер ЕРСП / система |
| действие | создание / изменение (архив — это изменение поля «статус») |
| таблица, номер записи, запись | название записи на момент изменения |
| страховая компания | для фильтра по страховой; пусто у общих справочников (банки) |
| поле, было, стало | значения как есть (у ссылок — номер записи, показ с названием) |

- Пишется при каждом сохранении записи, в той же транзакции: либо сохранилось
  и изменение, и строка журнала, либо ничего. Сохранение без изменений
  ничего не пишет; лишние пробелы изменением не считаются.
- У новой записи пишутся только заполненные поля; служебные поля
  «кто и когда» не пишутся.
- Обойти журнал нельзя: массовые операции (`update`, `delete`, `bulk_create`,
  `bulk_update`) и удаление записей для этих таблиц запрещены в коде.
- Строки журнала не меняются и не удаляются: триггер PostgreSQL отказывает
  в UPDATE, DELETE и TRUNCATE всем ролям, включая роль приложения.
  Снять триггер можно только миграцией (через git и человека).
- В админ-панели — раздел «Аудит → журнал изменений», только просмотр;
  кнопка «История» в карточке открывает изменения этой записи.
- Записи, созданные до появления журнала (банк 01095, стартовые списки),
  в нём не отражены.
- У строк вложенных записей (представитель, счёт, данные юрлица) есть ссылка
  на карточку-хозяина: «История» карточки показывает и их изменения
  (добавлено 20.10, миграция `audit/0002`; у прежних строк ссылка пуста,
  данные юрлица находятся по общему с карточкой номеру).

## Права

| Кто | Что может |
|---|---|
| Сотрудник | читать справочник; из формы полиса — создать контрагента, дописать пустые поля, применить отличия, которые вернул провайдер (с подтверждением) |
| Администратор справочников (группа; первый участник — Бекзод) | всё остальное: правка заполненных полей, архив, справочники |

Каждое действие сотрудника пишется в журнал с его именем.

Сделано 20.10 (миграция `accounts/0003_access_groups`):

| Группа | Права в админ-панели |
|---|---|
| Администратор справочников | контрагенты (карточка, данные юрлица, представители, счета), банки, должности, основания — заводить и править; архив и возврат из архива; справочники ЕРСП и журнал — просмотр |
| Сотрудник | всё то же — только просмотр. Группа пока пустая (решение 20.10); работа из формы полиса появится вместе с полисами |

- Удалять не может никто, даже суперпользователь: записи уходят в архив
  или получают отметку «не действует» / «закрыт».
- Для входа в админ-панель кроме группы нужны «статус персонала» и
  страховая компания в учётной записи. Суперпользователю группы не нужны.
- Сотрудник видит контрагентов и журнал изменений только своей страховой;
  изменения общих справочников (банки, должности) видны всем.
- «В архив» и «Вернуть из архива» — действия в списке контрагентов;
  каждая смена статуса — отдельной строкой журнала.
- Журнал просмотров ПИНФЛ и паспортных данных — вместе с интерфейсом
  сотрудников (решение 20.10).

## Данные провайдера

- Ответ храним целиком с датой (модуль интеграции).
- В карточку переносим с обрезанными пробелами; для поиска — нормализованная копия:
  провайдер смешивает кириллическую «а» с латиницей (`okedTitle`: «Hаyotni»).
- Отличия от нашей записи не перезаписываются молча: показываем и применяем
  после подтверждения.

### Заполнение по ИНН (решения Бекзода 20.10, до написания кода)

- Ответ провайдера целиком — в журнале обмена (модуль интеграции `integrations`),
  вместе с датой, средой, кем запрошен; журнал только пополняется.
- Запрос — только по кнопке («Новый контрагент по ИНН», «Сверить с провайдером»),
  не автоматически при открытии карточки. Иностранным — не запрашиваем.
- Сверка: «поле | у нас | у провайдера | применить». Пустые у нас поля
  отмечены заранее, отличия в заполненных — нет. Пустое у провайдера
  наше значение не стирает. Применённое пишется в журнал с источником
  «провайдер ЕРСП».
- Ответ дублирует поля (`nameShort` и `name_short`): берём camelCase.
- ОКЭД, которого нет в справочнике ЕРСП, не применяется — предупреждение.
- Руководитель (`gdFullName`) не совпал с основным представителем — это другой
  человек: по выбору сотрудника прежний закрывается сегодняшней датой,
  новый заводится основным (без должности и паспорта).
- Счёт от провайдера, которого нет у контрагента, добавляется неосновным;
  основным — только если основного нет. Новый МФО заводит банк (ИНН банка
  пустой — напомнит «Готовность к ЕРСП»).
- `district` (налоговая инспекция) — отдельной колонки нет, остаётся в ответе.
- Токен ЕРСП временный (`/oauth/v2/token`, срок `expires_in`). В секретах
  Podman — не токен, а данные для входа (`client_id`, `client_secret`, логин,
  пароль): `ersp_prod_credentials`, `ersp_sandbox_credentials`, заводятся
  `bin/ersp-secret`. Приложение получает токен само, держит только в памяти,
  берёт новый при истечении или ответе 401. В журнале обмена пароль,
  `client_secret` и токены заменены на `***`.
- Токены пока одной страховой (Mosaic); выбор данных для входа устроен
  по страховой компании, чтобы вторая страховая была новым секретом, а не
  переделкой кода.
- Справочник банков из перечня ЦБ (cbu.uz) — отдельным этапом после.

Сделано 20.10 (приложение `integrations`): клиент ЕРСП с входом и токеном
в памяти, журнал обмена (только пополняется, триггер в базе; секреты
скрыты), просмотр журнала в админ-панели (свои записи страховой; группам —
только просмотр), команда проверки `ersp_check`. Вход проверен на сервере 20.10: обе среды,
токен живёт 1 051 898 с (около 12 суток), каждый вход выдаёт новый.

Сделано 20.10 (`counterparties/provider.py`, страницы в админ-панели):
- «Сверить с провайдером ЕРСП» — кнопка в карточке местной организации;
  «Новый по ИНН» — кнопка в списке контрагентов (если ИНН уже есть —
  открывается сверка его карточки).
- Запрос уходит один раз по кнопке; страница сверки дальше работает
  со строкой журнала обмена (`?exchange=<номер>`): применяется ровно тот
  ответ, который видел сотрудник, обновление страницы не шлёт новый запрос.
  Ответ чужой страховой не принимается.
- Значения перед сверкой очищаются так же, как при ручном вводе (пробелы,
  цифры телефона), поэтому «12-uy  » и «12-uy» — не отличие. Капитал —
  в сумах, ОКЭД — только из справочника ЕРСП.
- ФИО руководителя сравнивается без учёта регистра и букв-двойников.
  Если руководитель уже есть среди действующих представителей — он
  становится основным, прежний основной остаётся представителем (не
  закрывается); если это новый человек — прежний закрывается сегодняшней
  датой.
- Без наименования у провайдера карточка по ответу не заводится.
- Права: сверять и заводить — у кого есть право правки / добавления
  контрагента (группа «Администратор справочников»). «Сотрудник» пока
  не может: работа из формы полиса появится вместе с полисами.

## Правила отправки в ЕРСП (модуль интеграции)

- Среда — явная настройка: чтение (провайдер, справочники) — боевая среда,
  отправка — песочница, пока не решено иначе. Данные для входа — в секретах
  Podman (см. «Заполнение по ИНН»).
- `inn`: местный — как есть; иностранный ровно из 9 символов — как есть;
  длиннее — `123456789`, настоящий ИНН в `comment`.
- Иностранная организация: `regionId` — регион нашей страховой компании,
  `oked` — `0`, настоящий ОКЭД — в `comment`.
- Местной обязательны: основание и его номер, ПИНФЛ, серия и номер паспорта
  представителя, МФО, ИНН банка, телефон. Иностранной обязательна эл. почта.
- `ownershipFormId` — только для страхователя.
- Журнал обмена: что отправили, что ответили, в какую среду, сверка
  «что ушло — что село».

### Проверка полноты перед отправкой (сделано 20.10, `counterparties/ersp.py`)

В карточке — блок «Готовность к ЕРСП»: два вывода, «как страхователь» и «как
выгодоприобретатель, застрахованный, владелец объекта», со списком того,
чего не хватает. Блок считается по сохранённой карточке.

| Нужно всем | Только местным | Только иностранным | Только страхователю |
|---|---|---|---|
| ИНН, полное наименование, адрес; основной представитель (ФИО) с действующим сроком; основной незакрытый счёт (номер, банк) | регион, ОКЭД, телефон; у основного представителя — основание и номер документа, ПИНФЛ, серия и номер паспорта; банк счёта — из справочника, с ИНН банка | эл. почта | форма собственности |

- Для ЕРСП берётся **основной** представитель и **основной** счёт; если основного
  нет — это пробел, «первый попавшийся» не берётся (решение 20.10).
- Форму собственности можно отправлять у любого участника договора, но
  обязательна она только страхователю (решение 20.10).
- **Открытый вопрос:** отклоняет ли ЕРСП страхователя без формы собственности —
  проверить в песочнице при тестировании продаж (например, ДМС).
