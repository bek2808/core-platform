# Хранилище файлов: модель

**Согласовано с Бекзодом 21.10.2026** (ответы на вопросы — в конце файла).
Решения 21.10:

- хранилище файлов делаем раньше этапа C «Вход»: без него нет отправки
  агентов в ЕРСП (часть B5, нужен PDF соглашения);
- в ЕРСП уходит только PDF, но само хранилище принимает и фото
  (JPG, PNG) — пригодятся для убытков и документов;
- загружают и заменяют скан соглашения те, кто работает с агентами
  (директоры подразделений и роль «Работа с агентами»), смотрят — все,
  кто видит агента;
- файлы лежат на том же диске, что и база (как и резервные копии;
  вторая площадка — вопрос 5 к администратору).

Первое применение — скан агентского соглашения (`agents.Agreement`).
Дальше тем же способом — договоры, убытки, документы клиентов.

## Главные принципы

- **Файл, загруженный в систему, не меняется и не удаляется.** Замена скана —
  новая версия; старая остаётся и открывается из истории. На файл может
  ссылаться то, что уже ушло в ЕРСП, — подменять его задним числом нельзя.
- **Файл видят те же люди, что видят запись, к которой он приложен.**
  Отдельных прав на файлы нет: скан соглашения открывает тот, кто видит
  агента (`accounts.visibility`). Чужая страховая — «не найдено»,
  администратор платформы — 403.
- **Прямой ссылки на файл нет.** Файл отдаёт только приложение, после
  проверки прав. По адресу из браузера, переданному другому человеку,
  файл без входа и без прав не откроется.
- **Защита контейнера не ослабляется** (правило 10 в AGENTS.md):
  запись разрешена только в одну папку — `/data/files`, всё остальное
  в контейнере по-прежнему только для чтения.
- **Целостность проверяется.** У каждого файла хранится отпечаток SHA-256:
  подмену или порчу файла на диске находит проверка `files_check`.

## Где лежат файлы

| Что | Где |
|---|---|
| Том Podman | `core-files` (файл `quadlet/core-files.volume`), владелец внутри тома — пользователь приложения в контейнере (UID 10001), чтобы `core-web` мог писать, а больше никто |
| Папка в контейнере `core-web` | `/data/files` (запись разрешена только сюда) |
| Путь файла в томе | `<id страховой>/<год>/<месяц>/<случайное имя>.<pdf/jpg/png>` |
| Временные файлы загрузки | `/data/files/.tmp` — на том же томе: готовый файл переносится на место одним действием (`rename`), наполовину записанный файл на месте появиться не может |

Имя файла на диске — случайное (UUID), а не то, что дал человек: имя
из Windows («Соглашение №5 (копия).pdf») может содержать что угодно,
и по нему нельзя угадать адрес чужого файла. Исходное имя хранится в базе
и подставляется при скачивании.

Почему том, а не MinIO (S3) и не база:
- MinIO — ещё один контейнер со своими обновлениями и паролями;
  для 20 пользователей это лишнее. Django хранит файлы через общий
  слой `STORAGES`, поэтому перейти на S3 позже можно без переписывания
  экранов;
- файлы в базе раздувают каждую резервную копию и замедляют её.

## Таблица `files.StoredFile` — загруженный файл

Запись создаётся один раз и больше не меняется: правка и удаление
запрещены триггером в базе (как у журнала изменений).

| Поле | Что | Правило |
|---|---|---|
| id | UUID | он же — имя файла на диске и часть адреса скачивания |
| страховая | `InsuranceCompany` | обязательна; файл другой страховой не виден |
| к чему приложен | вид записи + её id (например, соглашение № 12) | обязательно |
| назначение | слово: `agreement_scan` (скан соглашения), позже другие | от назначения зависят допустимые типы и размер |
| исходное имя | текст | как назвал файл человек; при скачивании — оно |
| тип | `application/pdf`, `image/jpeg`, `image/png` | определяется по содержимому файла, а не по окончанию имени |
| размер | байты | больше нуля |
| SHA-256 | 64 знака | отпечаток содержимого |
| путь | текст | относительно `/data/files` |
| загрузил, когда | `User`, время UTC | ставит система |

Текущая версия — ссылка из самой записи: у соглашения появляется поле
«скан» (`Agreement.scan` → `StoredFile`). Смена ссылки пишется в журнал
соглашения (было → стало), поэтому в «Истории» видно, кто и когда
заменил скан. Все версии — файлы этой записи с тем же назначением,
по времени загрузки.

## Правила загрузки

| Назначение | Типы | Размер |
|---|---|---|
| скан соглашения (`agreement_scan`) | только PDF | до 5 МБ (лимит ЕРСП) |
| остальные (позже) | PDF, JPG, PNG | до 15 МБ |

- Тип проверяется по первым байтам файла: PDF начинается с `%PDF-`,
  JPG — с `FF D8 FF`, PNG — с `89 50 4E 47`. Файл `вирус.exe`,
  переименованный в `скан.pdf`, не примется.
- Пустой файл не принимается.
- Фото с iPhone в формате HEIC пока не принимаем (браузеры его
  не показывают); телефон обычно сам отдаёт JPG при загрузке через браузер.
- Общий предел запроса настраивается в Django (`DATA_UPLOAD_MAX_MEMORY_SIZE`,
  `FILE_UPLOAD_MAX_MEMORY_SIZE`), чтобы огромный файл не занял память
  контейнера (лимит 1 ГБ на три процесса gunicorn).

## Скачивание и просмотр

- Адрес: `/files/<UUID>/`. Приложение находит запись, к которой приложен
  файл, и проверяет, видит ли её пользователь (`scope_for`). Нет — «не найдено».
- PDF и фото открываются в новой вкладке браузера, с заголовками,
  которые запрещают браузеру выполнять содержимое (`X-Content-Type-Options:
  nosniff`, `Content-Security-Policy: sandbox`).
- Каждое скачивание пишется в журнал просмотров: кто, когда,
  какой файл. В сканах соглашений бывают паспортные данные и ПИНФЛ —
  а 19.10 решили, что просмотр таких данных желательно фиксировать.

## Экран: скан в карточке соглашения

В блоке соглашений карточки агента у каждого соглашения:
- «Скан: Соглашение AZM-21-000.pdf (1,2 МБ, загружен 21.10.2026, Бекзод)» —
  ссылка открывает файл;
- кнопка «Загрузить скан» (если скана нет) или «Заменить скан»;
- «Версии (2)» — список прежних сканов со ссылками.

Загрузка и замена — отдельная страница-действие, как «Прекратить соглашение»
(`agents.services`, права и видимость те же). Ровность полей
закладывается сразу и проверяется замером (AGENTS.md).

## Резервные копии

- `bin/pg-backup` дописывается: после базы — архив тома
  (`podman volume export core-files`) в файл `files.tar` в той же папке
  копии с датой. Срок хранения тот же — 14 дней.
- Пока файлов мало, каждая копия — полный архив. Когда том вырастет
  (сотни мегабайт), перейдём на копирование только новых файлов:
  файлы не меняются, поэтому это просто.
- Восстановление проверяется так же, как у базы: распаковать копию
  во временный том и сверить `files_check` — у каждой записи есть файл
  и SHA-256 совпадает.

## Проверка `files_check`

Команда (`python manage.py files_check`) находит:
- записи, у которых нет файла на диске;
- файлы, у которых SHA-256 не совпадает с записью (порча или подмена);
- файлы на диске без записи (загрузка оборвалась после записи файла,
  до сохранения строки в базе), — только показывает, не удаляет.

## Тесты

- PDF до 5 МБ принимается; больше 5 МБ, пустой, «не PDF» с окончанием `.pdf`,
  JPG для скана соглашения — отказ с понятным текстом;
- файл чужой страховой — «не найдено»; администратор платформы — 403;
- видимость по подразделению: головной офис, руководитель филиала, отдел
  (как `agents/test_visibility.py`);
- запись `StoredFile` нельзя изменить и удалить даже в обход Django (триггер);
- замена скана — новая версия, старая открывается, в журнале соглашения
  было → стало;
- скачивание пишет строку журнала просмотров;
- `files_check` находит пропавший, испорченный и лишний файл.

Тесты пишут файлы во временную папку, а не в том.

## Порядок работ

| Часть | Что |
|---|---|
| F1 | Эта модель — согласовать |
| F2 | Том `core-files`, подключение к `core-web`, архив тома в `bin/pg-backup` |
| F3 | Приложение `files`: таблица, загрузка, скачивание, журнал просмотров, `files_check`; скан в карточке соглашения; тесты |
| F4 | Установка на сервер по шагам: место на диске, резервная копия, том, сборка, миграция, проверка руками |

Потом — B5 (отправка агента в песочницу ЕРСП со сканом).

## Ответы Бекзода (21.10)

1. Предел для фото и прочих файлов — 15 МБ; для скана соглашения — 5 МБ (ЕРСП).
2. Журнал просмотров файлов ведём сразу: кто, когда, какой файл.
3. PDF и фото открываются во вкладке браузера (с защитными заголовками).
4. Соглашение можно сохранить без скана; отправка агента в ЕРСП (B5)
   без скана не начинается — система говорит, чего не хватает.
